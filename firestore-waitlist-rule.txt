WAITLIST RULE — paste into the Firebase Console before the landing page goes live
=================================================================================

Without this, every "Notify me" submit fails with permission-denied.

WHERE:  console.firebase.google.com  →  project clo-beat-the-bank
        →  Firestore Database  →  Rules tab

HOW:    INSERT this block as its own match, INSIDE match /databases/{database}/documents
        and BEFORE the catch-all deny at the bottom. Do NOT paste over the whole file —
        the players / referralPayouts rules must stay exactly as they are.

--------------------------------------------------------------------------------
    match /waitlist/{uid} {
      // One doc per visitor, keyed by their anonymous auth uid, so a second
      // submit updates their own row instead of creating another.
      allow create, update: if request.auth != null
        && request.auth.uid == uid
        && request.resource.data.keys().hasOnly(['email','ref','createdAt'])
        && request.resource.data.email is string
        && request.resource.data.email.size() > 3
        && request.resource.data.email.size() < 200
        && request.resource.data.createdAt is number;

      // Nobody reads or deletes from the client. Read the list in the Console.
      allow read, delete: if false;
    }
--------------------------------------------------------------------------------

THEN:   click Publish, and wait for "Rules published successfully".

TEST:   open clochamps.com in an Incognito window, enter an address, submit.
        You should see "You're on the list."
        Then check Firestore Database → Data → waitlist for the row.
        If it fails, the browser console shows the real reason.

READING THE LIST LATER:
        Firestore Database → Data → waitlist. Each doc holds email, ref
        (the ?ref= referral code if they arrived on an invite link), and
        createdAt as a millisecond timestamp.
